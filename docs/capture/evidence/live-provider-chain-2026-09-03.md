# App-native live provider/archive proof — 2026-09-03

## Scope and privacy

The fixture was 18.034 seconds and 577,174 bytes of 16 kHz mono PCM synthesized
with two macOS system TTS voices. It contained no personal recording. The live
destinations were the existing TOS staging bucket, private GitHub repository
`xingfanxia/watch-transcriber-data`, and private R2 bucket
`watch-transcriber-audio`.

Existing user-owned TOS, 妙记, Gemini, GitHub, and R2 credentials were loaded
only into the test process environment and then written/read through EchoWall's
real platform secure-store adapters. They were never printed, copied into the
repository, or embedded in a binary. The two temporary Keychain entries were
deleted after the proof.

One diagnostic command accidentally enumerated filenames from the temporary
private archive checkout. It did not read note contents, audio, or credentials,
and did not transmit the names to a new external service, but it violated the
aggregate-only output boundary. The command was not repeated; all subsequent
archive checks used exact control paths or aggregate counts, and the entire
temporary checkout was deleted after reconciliation.

## TOS SDK dependency retirement

A current RustSec audit after the first proof found seven vulnerabilities, all
introduced by the latest available `ve-tos-rust-sdk` 2.9.20 through its old
reqwest 0.11, hyper/h2 0.3, Hickory 0.24/0.25, rustls 0.21, and webpki 0.101
graph. Upstream had no newer crate that could remove them. Adding audit ignores
would have hidden reachable upload-client code, so the App removed the SDK
dependency instead.

`processing/tos.rs` now owns a minimal TOS4 HTTP adapter for only the four
operations EchoWall uses: deterministic PUT, current/exact HEAD, exact-version
DELETE, and exact-version presigned GET. The signing algorithm and canonical
request shape are ported from the official SDK's Apache-2.0 source; transport is
the App's existing reqwest 0.13/rustls 0.23 stack with bundled roots, HTTPS-only,
no proxy, no redirect, no internal retry, and bounded connect/read/total
timeouts. Object key, source hash/size, recording metadata, CRC64, version ID,
and ETag checks are unchanged. A fixed fabricated presign vector generated by
the official SDK is reproduced exactly by the native signer.

The replacement then reran the complete live proof on a new 11.125-second,
356,086-byte two-system-voice fixture. The result was two Miaoji transcript
segments, both speaker-labelled, seven summary fields, one publication target,
a verified canonical R2 backup, a fresh matching archive refresh, exact TOS
cleanup, and verified GitHub/R2 deletion. Both secure-store entries were absent
afterward and the complete temporary root was permanently removed. No
diagnostic command enumerated the private checkout during this rerun.

After migration `cargo audit` scans 594 App-lock dependencies with zero known
vulnerabilities. It still reports non-fatal maintenance/yank warnings in
transitive platform crates; none is an ignored vulnerability result.

## Fail-safe recovery evidence and fixes

The first authorized run exposed six real migration defects. Every remote
effect was reconciled from the durable ledger before retrying; no ambiguous
妙记 submit, Gemini call, or GitHub publication was automatically repeated.

1. **TOS Rust SDK payload signing.** Supplying `content_sha256` to
   `ve-tos-rust-sdk` 2.9.20's file-upload input produced
   `403 SignatureDoesNotMatch`. The same parameters passed through the official
   Python SDK. The Rust adapter now lets the SDK sign its body stream while the
   independently computed SHA remains bound in the deterministic key, object
   metadata, local pre/post hash, and exact HEAD proof. The later native TOS4
   replacement preserves this verified signing rule without the vulnerable SDK
   transport graph.
2. **TOS versioning was not enabled.** A successful PUT returned no version ID,
   which the App correctly refused to checkpoint. The matching unversioned
   orphan was HEAD-verified and deleted. The bucket now reports versioning
   `Enabled` and has one enabled lifecycle rule for
   `echowall/processing/v1/` with noncurrent expiration at one day. The
   `.env.example` prefix was corrected to the actual object namespace.
3. **Wrong ASR resource ID.** The Rust port sent
   `volc.bigasr.auc_turbo`, contradicting the active 妙记 route and existing
   README/legacy provider. It now sends `volc.lark.minutes`; a contract test
   prevents regression. The first request was explicitly rejected and never
   accepted, so the ledger's explicit provider retry remained safe.
4. **Gemini schema drift.** The remote prompt/validator checked only `title`,
   allowing object-shaped `action_items` that the archive formatter rejected.
   Remote validation now deserializes the same closed
   `LocalSummaryDocument` contract as the local worker: exactly seven fields,
   fixed category set, and string arrays. A strict compatibility normalizer
   handles already-checkpointed `{task, owner?, due_date?}` items without a
   second Gemini call and rejects all other object fields/types.
5. **Private GitHub tarball redirect.** The shared HTTP client intentionally
   disables automatic redirects, while GitHub returns a signed 302 to
   `codeload.github.com`. Sync now follows exactly one HTTPS redirect bound to
   the configured owner/repository and known tarball path. It rejects other
   hosts, ports, userinfo, fragments, and encoded traversal, and never forwards
   the GitHub PAT to codeload; the signed query is sufficient.
6. **Deleting an R2-only audio path from Git.** Native delete sent `sha:null`
   for the friendly audio path even though canonical audio is not stored in the
   Git tree. GitHub correctly returned 422. Delete now emits null-tree entries
   only for paths present in the base tree; the separately owner-verified R2
   intent still removes canonical audio. The quarantined intent was restored
   to the outbox only after its base entry was proven byte-equivalent to remote,
   then replayed successfully.
